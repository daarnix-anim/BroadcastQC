# Broadcast QC — план разработки плагина для After Effects и Premiere

## 1. Цель проекта

Разработать инструмент **QC (Quality Control)** для проверки motion-design проектов перед рендером.

Основные задачи:

1. Проверка орфографии и очевидных текстовых ошибок.
2. Опциональная проверка выхода текста за TV Safe Zone.
3. Умное определение моментов, когда анимация текста закончилась и текст находится в стабильном состоянии.
4. Проверка Safe Zone только в стабильных состояниях, а не во время анимации.
5. Формирование понятного отчёта с возможностью перейти непосредственно к проблемному слою/таймкоду.
6. В перспективе — подключение локальной LLM для интеллектуальной проверки текста.

### Главный принцип

**Орфография проверяется всегда.**

**TV Safe Zone — отдельная опция и применяется только когда пользователь её включил.**

Обычные презентационные ролики не должны получать предупреждения Safe Zone.

# 3. Этап 0 — исследование API After Effects

Перед написанием основного кода необходимо изучить актуальные возможности AE API для поддерживаемой версии After Effects.

Нужно проверить:

- получение списка композиций;
- получение текстовых слоёв;
- получение содержимого TextDocument;
- получение transform properties;
- получение bounding box текста;
- получение keyframes;
- получение значения свойства в конкретный момент времени;
- получение длительности композиции;
- получение frame rate;
- получение текущего времени;
- переход к конкретному таймкоду;
- создание snapshot/render конкретного кадра;
- взаимодействие панели с AE.

Отдельно проверить ограничения:

- можно ли получать точный bounding box paragraph/point text;
- как ведут себя текстовые слои внутри precomp;
- как получать трансформации родительских слоёв;
- как работать с 3D layers;
- как учитывать scale/rotation/parenting;
- как получать фактические границы текста после всех трансформаций;
- как обрабатываются expressions;
- какие операции доступны из панели, а какие требуют другого механизма.

### Результат этапа

Создать:

`docs/AE_API_RESEARCH.md`

Документ должен содержать:

- доступные API;
- получаемые данные;
- ограничения;
- известные проблемы;
- предполагаемые workaround;
- решение о том, какой API/стек использовать для MVP.

**Не переходить к полноценному QC, пока критические API-вопросы не проверены.**

# 8. Главная задача — определение стабильного состояния текста

**Не проверять Safe Zone на каждом кадре.**

Пример:

```text
00:00 ───────────── 00:03
       animation

00:03 ───────────── 00:07
       stable

00:07 ───────────── 00:09
       animation

00:09 ───────────── 00:14
       stable
```

Проверять Safe Zone нужно примерно здесь:

```text
00:05
00:12
```

Главная задача алгоритма:

> понять, когда анимация текста закончилась и текст перешёл в стабильное состояние.

---

# 9. Stable State Detector

Для каждого текстового слоя анализировать его состояние через определённый временной интервал.

Например:

```text
sampling interval = 2–5 frames
```

Для каждого sample получать:

```text
position
scale
rotation
opacity
text
bounding box
```

Затем вычислять изменения:

```text
Δposition
Δscale
Δrotation
Δopacity
ΔboundingBox
```

Если изменения находятся ниже определённого порога на протяжении N кадров:

```text
STABLE
```

Если изменения превышают порог:

```text
ANIMATING
```

---

# 10. Не использовать слишком простой алгоритм

Нельзя делать:

```text
if position has no keyframe:
    stable
```

Это не учитывает:

- expressions;
- parent animation;
- precomp animation;
- scale animation;
- rotation animation;
- opacity animation;
- keyframes, которые фактически уже не меняют объект;
- движение через другие свойства.

Нужно анализировать **фактическое состояние объекта во времени**.

---

# 11. Stable Window

Стабильным считать не один кадр, а временное окно.

Например:

```text
stableWindow = 10–15 frames
```

Если объект остаётся практически неизменным в течение этого периода:

```text
STABLE STATE DETECTED
```

Для проверки Safe Zone выбрать кадр примерно в середине stable window.

Например:

```text
┌───────────────────────────────┐
│ stable window                 │
│                               │
│ 108 109 110 111 112 113 114  │
│             ↑                 │
│          CHECK FRAME          │
└───────────────────────────────┘
```

Параметры sampling interval, stable window и пороги должны быть конфигурируемыми.

---

# 12. Несколько Stable States

Один текстовый слой может иметь несколько состояний:

```text
0–3 sec     hidden
3–5 sec     animation
5–8 sec     stable
8–10 sec    animation
10–14 sec   stable
```

Необходимо получить:

```json
{
  "layer": "Title",
  "states": [
    {
      "start": 5,
      "end": 8,
      "type": "stable"
    },
    {
      "start": 10,
      "end": 14,
      "type": "stable"
    }
  ]
}
```

И проверить Safe Zone в каждом стабильном состоянии.

---

# 13. Изменение текста

Особенно важно отслеживать:

```text
TEXT A
  ↓
animation
  ↓
TEXT B
```

Если содержимое текстового слоя меняется:

```text
"Продукт"
      ↓
"Новый продукт"
```

это должно считаться новым состоянием.

После изменения текста снова искать stable state.

---

# 14. Screenshot / Frame Capture

На каждом найденном stable state сделать screenshot/render frame.

Например:

```text
Scene 01
 ├─ stable state 01 → frame 142
 ├─ stable state 02 → frame 317
 └─ stable state 03 → frame 521
```

Screenshot нужен для:

1. визуального отчёта;
2. ручной проверки;
3. будущего AI анализа.

**Не использовать screenshot как основной источник координат Safe Zone.**

Для Safe Zone сначала использовать структурированные данные AE и геометрию слоя.

Screenshot — дополнительный визуальный источник.

---

# 15. Проверка Safe Zone

Для каждого stable state:

```text
Text Bounding Box
        ↓
Transform to Composition Space
        ↓
Safe Zone
        ↓
Intersection
```

Результат:

```json
{
  "status": "error",
  "side": "left",
  "overflow": 24,
  "time": 5.43
}
```

Пример отчёта:

```text
🔴 Title_Main

00:05:43

Текст выходит за Safe Zone.
Левая граница: 24 px.
```

---

# 16. Геометрия Safe Zone

Алгоритм должен учитывать:

- положение;
- scale;
- rotation;
- anchor point;
- parent transforms;
- размеры текста;
- composition resolution;
- при необходимости 3D transforms.

Для MVP сначала явно зафиксировать ограничения.

Если точный расчёт для какого-то типа слоя невозможен, результат должен быть:

```text
WARNING / MANUAL REVIEW
```

а не ложный PASS.

# 17. Какие элементы проверять в MVP

На первом этапе:

**Только native AE text layers.**

Позже:

- text inside precomp;
- shape-based text;
- subtitles;
- MOGRT;
- Essential Graphics;
- Premiere captions.

Не пытаться реализовать всё сразу.

# 22. AI Layer — второй этап

После стабильного MVP добавить:

```text
AI QC
```

AI должен быть отдельным сервисом.

API:

```text
POST /analyze-text
POST /analyze-frame
```

Первоначально поддержать локальную модель.

Пример архитектуры:

```text
AE
 ↓
Local QC Server
 ↓
LanguageTool
 ↓
Local LLM
```

LLM использовать для:

- контекстных ошибок;
- подозрительных опечаток;
- пунктуации;
- единообразия терминологии;
- сравнения текстов;
- анализа screenshots;
- выявления неоднозначных случаев.

LLM не должна заменять детерминированную геометрическую проверку Safe Zone.

# 23. Локальный QC Server

Создать отдельный локальный процесс:

```text
qc-server
```

Например:

```text
http://127.0.0.1:PORT
```

AE Plugin общается с ним через localhost HTTP API.

Это позволит позже подключать:

```text
LanguageTool
Ollama
LM Studio
OpenAI-compatible API
другие API
```

без изменения AE Plugin.

# 28. Что НЕ делать на первом этапе

Не пытаться сразу реализовать:

- Premiere;
- AI;
- автоматическое исправление текста;
- анализ shapes;
- анализ всех precomp;
- блокировку рендера;
- сложный визуальный редактор Safe Zone;
- облачный сервер.

Сначала доказать две вещи.

### A — корректное получение текста и геометрии

Плагин должен правильно получать:

- текст;
- bounding box;
- transform;
- композиционные координаты.

### B — корректное определение состояния

Алгоритм должен правильно определять:

```text
ANIMATION
     ↓
STABLE
     ↓
CHECK
```

Это ядро проекта.

# 29. MVP Definition of Done

MVP считается готовым, если:

- [ ] AE Plugin запускается.
- [ ] Можно просканировать композицию.
- [ ] Все native text layers обнаруживаются.
- [ ] Текст извлекается.
- [ ] Bounding Box определяется корректно.
- [ ] Орфография проверяется.
- [ ] Есть пользовательский словарь.
- [ ] Safe Zone можно включить/выключить.
- [ ] Можно создать Custom Safe Zone.
- [ ] Определяются animation/stable states.
- [ ] Safe Zone проверяется только в stable states.
- [ ] Создаются screenshots контрольных кадров.
- [ ] Ошибки отображаются в отчёте.
- [ ] По ошибке можно перейти к слою и таймкоду.
- [ ] Есть automated tests на основные сценарии.
- [ ] AI является необязательным модулем.

AI не должен компенсировать ненадёжную базовую архитектуру.

# 32. Ключевой пользовательский сценарий

Типичный презентационный ролик:

```text
Пользователь открывает AE
        ↓
Открывает QC
        ↓
Нажимает CHECK
        ↓
Плагин находит все текстовые слои
        ↓
Проверяет орфографию
        ↓
Safe Zone выключена
        ↓
Показывает ошибки
```

ТВ-проект:

```text
Пользователь открывает AE
        ↓
QC
        ↓
☑ Spelling
☑ TV Safe Zone
        ↓
Выбор Safe Zone Template
        ↓
CHECK
        ↓
Анализ текста
        ↓
Определение stable states
        ↓
Проверка Safe Zone
        ↓
Screenshots контрольных кадров
        ↓
QC Report
```

Во время анимации:

```text
TEXT
  │
  ├── moves outside Safe Zone
  │
  ├── moves back
  │
  ▼
STABLE
  │
  ▼
CHECK
```

Нарушение Safe Zone во время движения **не является ошибкой**.

Нарушение Safe Zone после завершения анимации **является ошибкой**.

# 33. Главная концепция продукта

Это не просто spellchecker и не просто Safe Zone overlay.

Основная идея продукта:

> **Автоматический QC для motion-design проектов, который понимает временное поведение текста и проверяет только те состояния, которые действительно должны быть корректными.**

Ключевое преимущество:

```text
Не:
"Текст когда-нибудь оказался за Safe Zone"

А:
"После завершения анимации текст остался за Safe Zone"
```

Именно это должно быть центральным принципом всей архитектуры.

# 34. Задание для Claude Code

При начале реализации Claude Code должен:

1. Сначала изучить существующую структуру проекта.
2. Не писать весь проект одним этапом.
3. Начать с `PHASE 0`.
4. Создать `docs/AE_API_RESEARCH.md`.
5. Зафиксировать выбранный стек и ограничения.
6. После этого реализовать минимальный AE Analyzer.
7. Добавить автоматические тесты.
8. Для Stable State Detector создать отдельный модуль с тестами на синтетических временных рядах.
9. Только после успешного прохождения тестов переходить к Safe Zone.
10. Не добавлять AI до завершения детерминированного QC.
11. Все настройки делать конфигурируемыми.
12. Не смешивать Adobe-specific код с `qc-core`.
13. Документировать каждое API-ограничение Adobe.
14. Не делать Premiere Adapter до завершения AE MVP.

### Особое требование

Нужно оптимизировать систему под реальную работу motion designer:

- минимум ручных действий;
- отсутствие ложных предупреждений;
- быстрый анализ;
- понятные сообщения;
- переход к проблемному слою/таймкоду;
- возможность отключить TV Safe Zone;
- работа без облачного AI;
- возможность в будущем подключить локальную LLM.

# 35. Первая задача для Claude Code

Начать только с:

```text
PHASE 0 — AE API Research
```

Не реализовывать остальные фазы, пока не будет подготовлен документ с выводами по API и подтверждено, что необходимые данные для:

- получения текста;
- получения фактических transform values;
- получения bounding box;
- оценки состояния во времени;
- перехода к таймкоду;
- получения screenshot/frame;

действительно доступны в выбранной архитектуре.

После подтверждения перейти к:

```text
PHASE 1 — Minimal AE Analyzer
```

и создать минимальный рабочий прототип, который выводит список текстовых слоёв и их параметры.
